# 階段 03：ML 訓練管線瓶頸診斷

[課綱](ROADMAP.md)｜[進度](../PROGRESS.md)｜[帶練方式](TEACHING.md)

## 要解決的問題

GPU 等待時，問題究竟在資料讀取、CPU 處理、傳輸，還是 GPU 運算？

前置：階段 02；階段 01 的訓練機制。

## 必要觀念

完整訓練 step 包含取 batch、H2D、forward、loss、backward、optimizer。Profiler 用來定位時間路徑，帶 trace 的速度不直接當常態吞吐。

## 逐步練習

以下按多次教學進行，每次只取一個操作，先講清楚再等待結果。未確認環境前不預寫安裝或訓練命令。

1. 固定小型 CNN 與授權清楚的公開影像資料，記錄資料版本、切分、batch 與品質檢查。
2. 先做 GPU 常駐合成資料，再做 CPU 合成資料，最後做本機真實資料；三者是診斷對照，不當同一工作負載的加速比較。
3. 在取 batch、H2D、forward、backward、optimizer 加標記，讀一份短 CPU／GPU timeline。
4. 只根據 trace 選第一個假設，例如 workers 或資料處理造成等待，預測哪段應縮短。
5. 控制變因做 A/B，記錄 samples/s、CPU／RAM、顯存、loss 與 GPU 空檔；重新找瓶頸。
6. 完成第二輪診斷，可測 pinned memory、傳輸或布局；沒有資料瓶頸就不強迫增加 worker。

## 可驗收成果

一份可開啟 timeline、時間分解、兩輪有預測與原始資料的 A/B；能說明接受或放棄調整的理由。

每個實驗保存目的與假設、環境／輸入、命令、正確性、原始數據、圖與判讀。調整採用或放棄都需理由；用小變化驗證可獨立理解。

## 面試練習

為何 GPU 常駐合成資料很快，真實資料很慢？workers 加倍為何可能更慢？

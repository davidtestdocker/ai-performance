# 階段 04：C／C++ 與 CUDA 資料移動

[課綱](ROADMAP.md)｜[進度](../PROGRESS.md)｜[帶練方式](TEACHING.md)

## 要解決的問題

底層資料布局與傳輸如何限制端到端訓練？

前置：階段 00 與 03；已看過一份訓練 trace。

## 必要觀念

先理解 C 指標、長度與邊界，再理解 C++ 容器和 RAII 的資源生命週期。GPU kernel 由 thread／block 執行；連續存取、傳輸與啟動成本影響效能。

## 逐步練習

以下按多次教學進行，每次只取一個操作，先講清楚再等待結果。未確認環境前不預寫安裝或訓練命令。

1. 寫小型 C 陣列函式，明確傳入指標與長度，核對空輸入和邊界；透過受控範例學越界診斷。
2. 用 C++ vector 與 RAII 管理同一工作，說明生命週期及連續記憶體。
3. 建立可逐元素核對的 CPU 參考版與 CUDA 向量運算，檢查 CUDA 錯誤及數值容忍度。
4. 改輸入大小，分開量 H2D、kernel、D2H 與端到端；有效頻寬寫出 bytes 與單位。
5. 比較連續／跨步存取或兩個 block size；先預測再量，必要時用 Nsight Compute 下鑽。
6. 將資料移動結論連回階段 03 的 H2D 或 kernel trace；不要求自製大型 CUDA 框架。

## 可驗收成果

C／C++ 程式可自行修改與解釋；CPU／GPU 逐元素相符；有分段時間、頻寬曲線和受控實驗。

每個實驗保存目的與假設、環境／輸入、命令、正確性、原始數據、圖與判讀。調整採用或放棄都需理由；用小變化驗證可獨立理解。

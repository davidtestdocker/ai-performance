# 第 06 週：CPU 平行化、NUMA 與測試整合

[固定課綱](../../ROADMAP.md)｜[進度](../../../PROGRESS.md)｜[帶練規則](../../TEACHING.md)

**固定目標：** 量測單機 CPU 平行效率並用證據分辨運算與記憶體限制。

**職缺對應：** A 自動化測試與數據分析；D 分散式軟硬體調校的 CPU 基礎

**設備：** 一台多 vCPU Linux VM；NUMA 不存在則做設計分析

**先備：** 前 05 週必要驗收通過；新工具仍從最小例子開始。

| 日 | 主題 | 可觀察驗收 |
|---|---|---|
| [D01](day-01/README.md) | OpenMP 基礎 | 兩種 thread 數皆正確，能解釋每個 thread 寫哪些元素。 |
| [D02](day-02/README.md) | Reduction 與浮點誤差 | 容差有依據且能抓刻意錯誤，不用放大容差掩蓋 race。 |
| [D03](day-03/README.md) | 強擴展與 Amdahl | 圖含基準、thread 數與變異；能用序列成本解釋未線性加速。 |
| [D04](day-04/README.md) | Affinity、NUMA 與頻寬 | 實測和設計分開，記錄 cpuset 限制，不把 VM 的單 node 當實體 NUMA 結論。 |
| [D05](day-05/README.md) | CPU 階段整合驗收 | 獨立重現、無硬編碼結果，至少一個假說被資料支持或否定，所有差異可追溯。 |

## 本週成果與通關

必交：**OpenMP 擴展曲線與 CPU 自動化成果**。五日驗收全部通過，且能獨立修改小輸入、重新執行與解釋結果，才可進下一週。

實驗報告需有問題、環境、原始資料、正確性、方法、結果與限制。不得要求湊出正向加速；未取得硬體計數器需明列替代證據。第 23 週以原理與診斷設計通關，硬體實測為選修。

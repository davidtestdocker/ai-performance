# 第 04 週：C 從零與記憶體正確性

[固定課綱](../../ROADMAP.md)｜[進度](../../../PROGRESS.md)｜[帶練規則](../../TEACHING.md)

**固定目標：** 從編譯、型別、指標開始親寫可驗證的 CPU kernel。

**職缺對應：** A 自動化測試與數據分析；D 分散式軟硬體調校的 CPU 基礎

**設備：** 一台 Linux CPU VM；GCC/Clang

**先備：** 前 03 週必要驗收通過；新工具仍從最小例子開始。

| 日 | 主題 | 可觀察驗收 |
|---|---|---|
| [D01](day-01/README.md) | 編譯與型別 | 無未解釋警告，能解釋 3/2 與 3.0/2 的差異。 |
| [D02](day-02/README.md) | 迴圈、函式與陣列 | 輸出逐元素正確，n=0 不存取元素，測試不是只比總和。 |
| [D03](day-03/README.md) | 指標與生命週期 | 能解釋 & 與 *，不回傳區域陣列的位址。 |
| [D04](day-04/README.md) | 配置、釋放與錯誤 | 正常與異常路徑皆釋放，sanitizer 無未解決報告，保留編譯選項。 |
| [D05](day-05/README.md) | 計時與最佳化前基線 | 至少五次計算時間，結果被使用，sanitizer 時間不混入正式基準。 |

## 本週成果與通關

必交：**具邊界測試與 sanitizer 紀錄的向量加法**。五日驗收全部通過，且能獨立修改小輸入、重新執行與解釋結果，才可進下一週。

實驗報告需有問題、環境、原始資料、正確性、方法、結果與限制。不得要求湊出正向加速；未取得硬體計數器需明列替代證據。第 23 週以原理與診斷設計通關，硬體實測為選修。

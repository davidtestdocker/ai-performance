# 第 18 週：跨節點 TCP 與網路效能

[固定課綱](../../ROADMAP.md)｜[進度](../../../PROGRESS.md)｜[帶練規則](../../TEACHING.md)

**固定目標：** 在兩台不同 CPU VM 建立可信網路基線與瓶頸診斷。

**職缺對應：** D 分散式軟硬體調校；A 可信量測

**設備：** 兩台不同 Linux CPU VM，同 zone 私有網路優先

**先備：** 前 17 週必要驗收通過；新工具仍從最小例子開始。

| 日 | 主題 | 可觀察驗收 |
|---|---|---|
| [D01](day-01/README.md) | 雙主機拓樸與連通 | 證據包含兩個不同 VM 身分，明確標出同 zone 或跨區，不用 localhost 代替。 |
| [D02](day-02/README.md) | iperf3 TCP 基線 | 兩方向各重複三次，記 server/client 版本、重傳、CPU 與平均吞吐。 |
| [D03](day-03/README.md) | RTT、重傳與佇列 | 提出至少兩個假說與可區分的觀測，不能只看到低吞吐就調 buffer。 |
| [D04](day-04/README.md) | CPU 與網路交互影響 | 把 CPU 飽和、steal 與吞吐關聯寫清楚，不把相關當因果。 |
| [D05](day-05/README.md) | TCP 調校驗收 | 完整雙節點證據、三次重複與限制；不必修改核心參數才算完成。 |

## 本週成果與通關

必交：**雙主機 TCP 吞吐/延遲與系統觀察報告**。五日驗收全部通過，且能獨立修改小輸入、重新執行與解釋結果，才可進下一週。

實驗報告需有問題、環境、原始資料、正確性、方法、結果與限制。不得要求湊出正向加速；未取得硬體計數器需明列替代證據。第 23 週以原理與診斷設計通關，硬體實測為選修。

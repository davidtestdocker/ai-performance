# 第 03 週：自動化效能測試與數據分析

[固定課綱](../../ROADMAP.md)｜[進度](../../../PROGRESS.md)｜[帶練規則](../../TEACHING.md)

**固定目標：** 建立重複、錯誤分類、統計與可重現圖表的測試工具。

**職缺對應：** A 自動化測試與數據分析；D 分散式軟硬體調校的 CPU 基礎

**設備：** 一台 Linux CPU VM

**先備：** 前 02 週必要驗收通過；新工具仍從最小例子開始。

| 日 | 主題 | 可觀察驗收 |
|---|---|---|
| [D01](day-01/README.md) | 計時與暖機 | 每筆包含輸入量、elapsed_s 與 trial；不得將暖機悄悄併入穩態。 |
| [D02](day-02/README.md) | 子程序與失敗分類 | 三類結果都有狀態、stderr 與耗時，失敗不計入成功吞吐。 |
| [D03](day-03/README.md) | 統計與樣本分布 | 摘要含 n、median、min/max、失敗率；不以五筆宣稱穩定尾延遲。 |
| [D04](day-04/README.md) | 受控 A/B 與圖表 | 正確性一致，圖可由命令重建；說明波動下是否足以支持差異。 |
| [D05](day-05/README.md) | 回歸驗收與報告 | 乾淨目錄能產生 CSV、圖、報告；門檻由實測波動決定，測試資料不當實測。 |

## 本週成果與通關

必交：**benchmark runner、原始 CSV、摘要圖與回歸規則**。五日驗收全部通過，且能獨立修改小輸入、重新執行與解釋結果，才可進下一週。

實驗報告需有問題、環境、原始資料、正確性、方法、結果與限制。不得要求湊出正向加速；未取得硬體計數器需明列替代證據。第 23 週以原理與診斷設計通關，硬體實測為選修。

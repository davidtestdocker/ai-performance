# 第 22 週：分散式系統與儲存調校

[固定課綱](../../ROADMAP.md)｜[進度](../../../PROGRESS.md)｜[帶練規則](../../TEACHING.md)

**固定目標：** 結合 CPU、網路、儲存與排程指標診斷真實工作。

**職缺對應：** D 分散式軟硬體調校；A 可信量測

**設備：** 兩台 CPU VM；單 GPU 可分時使用

**先備：** 前 21 週必要驗收通過；新工具仍從最小例子開始。

| 日 | 主題 | 可觀察驗收 |
|---|---|---|
| [D01](day-01/README.md) | 儲存基準與工作量 | 不對裸裝置或既有檔案寫入，報 latency/IOPS/throughput 與 cache/direct 設定。 |
| [D02](day-02/README.md) | 訓練輸入與檔案布局 | 資料內容與樣本數一致，記預處理成本和容量，不把不同資料當 A/B。 |
| [D03](day-03/README.md) | 跨節點資源競爭 | 不超額啟動大量程序，指出一個受證據支持的資源競爭或無競爭結果。 |
| [D04](day-04/README.md) | 通訊與計算重疊 | 不把各段重疊時間直接相加，所有推論附可驗證方法。 |
| [D05](day-05/README.md) | 系統調校整合 | 兩案原始資料可重現，串起 OS/應用指標，無改善也能解釋下一步。 |

## 本週成果與通關

必交：**兩個系統調校案例與診斷決策表**。五日驗收全部通過，且能獨立修改小輸入、重新執行與解釋結果，才可進下一週。

實驗報告需有問題、環境、原始資料、正確性、方法、結果與限制。不得要求湊出正向加速；未取得硬體計數器需明列替代證據。第 23 週以原理與診斷設計通關，硬體實測為選修。

# 第 01 週：Linux 系統效能與 CPU 架構

[固定課綱](../../ROADMAP.md)｜[進度](../../../PROGRESS.md)｜[帶練規則](../../TEACHING.md)

**固定目標：** 建立 CPU、記憶體、程序與量測基線，能區分忙碌與等待。

**職缺對應：** A 自動化測試與數據分析；D 分散式軟硬體調校的 CPU 基礎

**設備：** 一台 Linux CPU VM

**先備：** 能登入 Linux VM；不要求 Python/C/CUDA/ML 基礎。

| 日 | 主題 | 可觀察驗收 |
|---|---|---|
| [D01](day-01/README.md) | CPU 拓樸與虛擬化 | 保存 lscpu 原始輸出，能指出 vCPU 數、架構與虛擬化限制，不推測宿主拓樸。 |
| [D02](day-02/README.md) | 程序、執行緒與排程 | 以時間戳記錄負載前中後，解釋程序狀態與每程序 CPU 百分比的計算範圍。 |
| [D03](day-03/README.md) | 記憶體與分頁 | 正確區分 RSS、page cache、swap 與 available，記錄至少 10 個採樣點。 |
| [D04](day-04/README.md) | CPU、I/O 與 steal 判讀 | 保存兩組至少 10 秒紀錄；沒有 steal 或 I/O 活動時如實寫無觀察證據。 |
| [D05](day-05/README.md) | 可信基線 | 交付基線表，能解釋 sleep 的 wall 大於 CPU time；記錄 VM 規格與背景負載。 |

## 本週成果與通關

必交：**主機盤點、三種負載觀察表與基線報告**。五日驗收全部通過，且能獨立修改小輸入、重新執行與解釋結果，才可進下一週。

實驗報告需有問題、環境、原始資料、正確性、方法、結果與限制。不得要求湊出正向加速；未取得硬體計數器需明列替代證據。第 23 週以原理與診斷設計通關，硬體實測為選修。

# 第 09 週：Nsight 與 GPU 瓶頸診斷

[固定課綱](../../ROADMAP.md)｜[進度](../../../PROGRESS.md)｜[帶練規則](../../TEACHING.md)

**固定目標：** 以 timeline 和 kernel 指標區分傳輸、啟動、頻寬與計算限制。

**職缺對應：** B ML 效能分析；C LLM 訓練效能分析的 GPU 基礎

**設備：** 一張 NVIDIA GPU；計數器權限依環境

**先備：** 前 08 週必要驗收通過；新工具仍從最小例子開始。

| 日 | 主題 | 可觀察驗收 |
|---|---|---|
| [D01](day-01/README.md) | Nsight Systems 時序 | 保存 trace 取得方式與摘要，能指出最大的端到端時間區段。 |
| [D02](day-02/README.md) | NVTX 與分段歸因 | range 清楚對應程式，記錄 profiler overhead，不拿 trace run 當正式吞吐。 |
| [D03](day-03/README.md) | Nsight Compute 指標 | 區分實際取得與未取得指標，不能把 replay 耗時當應用基準。 |
| [D04](day-04/README.md) | Roofline 與算術強度 | 公式與假設完整，不將有效 bytes 當硬體計數器實測流量。 |
| [D05](day-05/README.md) | 單 GPU 診斷閉環 | 交付基準、修正、正確性、重複分布與限制，現場換尺寸可再驗證。 |

## 本週成果與通關

必交：**Nsight 診斷報告與一個受控調整**。五日驗收全部通過，且能獨立修改小輸入、重新執行與解釋結果，才可進下一週。

實驗報告需有問題、環境、原始資料、正確性、方法、結果與限制。不得要求湊出正向加速；未取得硬體計數器需明列替代證據。第 23 週以原理與診斷設計通關，硬體實測為選修。

# 第 16 週：LLM 訓練 Profiling 與記憶體模型

[固定課綱](../../ROADMAP.md)｜[進度](../../../PROGRESS.md)｜[帶練規則](../../TEACHING.md)

**固定目標：** 量化 attention、MLP、optimizer、資料與 checkpoint 成本。

**職缺對應：** C LLM 訓練效能分析；A 可信量測

**設備：** 一張 GPU

**先備：** 前 15 週必要驗收通過；新工具仍從最小例子開始。

| 日 | 主題 | 可觀察驗收 |
|---|---|---|
| [D01](day-01/README.md) | 有效 token 基準 | 至少五次獨立短跑，配置與 token 計數可重建，與生成速度分開。 |
| [D02](day-02/README.md) | LLM timeline | 指出至少兩個主要成本及證據，不相加重疊或巢狀時間。 |
| [D03](day-03/README.md) | 參數與 optimizer 記憶體 | 理論估算和實測差異有解釋，保留 allocator 與暫存限制。 |
| [D04](day-04/README.md) | 序列長度與 attention 成本 | 不混淆吞吐與單步延遲，能預測較長序列的資源壓力。 |
| [D05](day-05/README.md) | Checkpoint 與輸入成本 | 報告常態與含 checkpoint 平均吞吐，品質設定不變，容量與寫入時間可追溯。 |

## 本週成果與通關

必交：**LLM 基線與記憶體/時間分解報告**。五日驗收全部通過，且能獨立修改小輸入、重新執行與解釋結果，才可進下一週。

實驗報告需有問題、環境、原始資料、正確性、方法、結果與限制。不得要求湊出正向加速；未取得硬體計數器需明列替代證據。第 23 週以原理與診斷設計通關，硬體實測為選修。

# 四大能力驗收與不誇大的邊界

依據：使用者提供的鴻海 HPC AI 效能工程師四項職責。完整招聘原文尚未提供；不把所有工具說成雇主指定，也不保證錄取或取代企業規模經驗。

| 能力 | 必要成果 | 通關門檻 | 不能宣稱 |
|---|---|---|---|
| A 自動化測試與數據分析 | Python runner、CPU/CUDA tests、原始 CSV、重建圖與回歸規則 | 正確性、失敗/timeout、環境版本、重複統計與乾淨重跑均可展示 | 只跑一次或只挑最快樣本是可信基準 |
| B ML 效能分析 | 真實訓練、PyTorch/Nsight trace、資料/計算各一調校實驗 | 梯度更新正確、品質未有未解釋退化、能以證據定位與再驗證 | GPU utilization 高就有效率 |
| C LLM 訓練效能分析 | 自寫小 GPT、標準模型、SDPA/checkpoint/累積實驗 | backward/step 真執行，有效 tokens/s、顯存、品質與恢復證據 | 生成或 inference 等於訓練；單卡等於多卡 |
| D 分散式軟硬體調校 | 雙節點 TCP、MPI、Slurm、CPU Gloo/DDP、系統案例及 RDMA/NCCL 設計 | 不同 VM 證據、正確性、placement、擴展與失敗診斷可重現 | Gloo 數據是 NCCL；TCP 或 Soft-RoCE 是硬體 RDMA |

## 課程選擇原則

核心工作必做，支援工作的基礎也必做：Python 用來測試/分析；C/C++ 用來寫 CPU/CUDA kernel；架構用來解釋 cache/頻寬/並行；梯度與 Transformer 用來檢查真訓練與效能。小型教學例子是實務能力的可驗證縮小版本，不宣稱它就是企業生產系統。

不安排與成果無關的平台重建、Linux 操作入門、競賽刷題或純工具安裝週。Linux perf/sysstat、CUDA/Nsight、PyTorch、MPI、Slurm 等為對應工作選用的工具，不聲稱目標團隊一定使用全部。標準工具的學習要落在真實問題和證據。

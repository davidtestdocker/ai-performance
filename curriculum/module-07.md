# 模組 07：TCP 網路效能與協定判讀

[路線](ROADMAP.md)｜目標：量測兩台 Linux 主機的實際網路路徑，能解釋吞吐、RTT、重傳與 CPU 開銷。

[觀念講義](CONCEPTS.md)第 07 節｜[作品成果](OUTCOMES.md)

## 學習大綱

TCP/網卡路徑 → 跨主機基準 → RTT/吞吐／重傳觀察 → 受控變因 → 協定與環境限制判讀。

## 先理解

NIC、link speed、MTU、TCP connection、window、RTT、重傳、buffer、吞吐與 tail latency。區分單機 loopback 和真正跨主機流量；區分網路 benchmark 與應用端到端時間。先畫出 client → NIC → 網路 → NIC → server 路徑。

## 實作

1. 盤點兩台主機的 NIC、IP、路由、MTU、速率和網路拓撲；記錄是否同區域／同交換網路，以及虛擬化限制。確認兩個不同 hostname/IP。
2. 用可重現的 TCP 工具做單連線與多連線吞吐測試、短訊息往返延遲測試；固定並記錄 payload 大小、連線數、持續時間與方向。
3. 同步保存 `ss -ti`、`ip -s link`、`ethtool -S` 中可用的 RTT、重傳、丟包或 NIC counters；若權限允許，擷取少量封包核對連線與重傳。資料要能對上測試時段。
4. 設計一個受控改變，例如訊息大小或並行連線數，先預測瓶頸會如何變化，再用原始資料檢查。避免把雲端共享網路的波動誤寫成協定必然性。

## 做完留下的成果

兩台主機的身分與路徑、原始吞吐／RTT、至少一張曲線、系統／封包指標，以及一份解釋小訊息延遲與大訊息吞吐差異的報告。只有單機時先保留功能結果，跨節點結果待兩台主機實測。
